CHAPTER 1 : INTRODUCTION

1.1 Background

Most local gyms are still run using paper notebooks and messy registers, which makes tracking memberships and daily operations a major headache and can easily lose the track of the gym. We built FitHub to fix these problems by replacing chaotic paperwork with a single, simple web platform. The system gives administrators complete control, allowing them to oversee the entire facility, track member statuses, and handle payments all from one secure dashboard. By bringing everything into one digital space, FitHub keeps the business organized.

1.2 Problem statements

Running a gym with paper notebooks and registers is slow, messy, and leads to easy mistakes. Owners constantly lose track of whose membership is expiring, who still owes money, etc. Because all the information is scattered, it is almost impossible to quickly check monthly income or see if the business is actually growing. This manual paperwork creates daily chaos and makes it really hard to run the gym smoothly as more members join.

1.3 Purpose of project

  • Get rid of paper registers: The gym currently uses only paper notebooks and diaries, which are messy, take up space, and can easily get lost or ruined.
  • Fix manual mistakes: Right now, the staff has to flip through pages by hand just to see who paid, who is new, or whose membership is ending, which takes way too long.
  • Give the gym its very first online system: This gym has absolutely no digital platform right now, so this project moves them from old-school paperwork to the internet for the first time.
  • Put everything in one place: Instead of checking different notebooks, the owner can now see members and fees all on one simple computer screen.
  • Save time and effort: By stopping the boring paperwork, the gym staff can stop stressing over daily records and focus on running a better fitness center.

1.4 Objective of project

  • To build a simple web application called FitHub that replaces all physical registers and paper notebooks with a digital system.
  • To create a central dashboard where the gym admin can view and manage members, and payments all in one place.
  • To automate the tracking of membership expiration dates and pending fees so the staff doesn't have to check records by hand.
  • To secure the gym's data by setting up proper login accounts for administrators and members.
  • To provide the gym with its very first online platform, moving their entire business from manual files to the internet.

1.5 Scope of the Project

The scope of this project is to build a web-based platform called FitHub specifically for a local gym that currently uses manual paper registers. The system moves all member records, membership packages, and transactions online. It provides secure login access for both the administrator and gym members, allowing the gym to process digital payments and communicate with members automatically, making daily operations entirely paperless.

1.5.1 Features:

Secure login system for admins and gym members.

Digital registration forms to quickly sign up new members.

Dynamic package creation for different gym membership tiers.

Integrated secure online checkout for membership fees.

Instant email receipts sent automatically upon payment confirmation.

Automated text and email alerts for upcoming membership expiration dates.

Search bar to instantly find any member's details by name or phone number.

In-gym product store with cart, orders and order receipts.

Member progress tracking (weight and body measurements) with charts.

Member reviews and ratings with admin moderation.

Gym calendar for classes, events and holidays, plus homepage banners.

1.5.2 Exclusions

Trainer Management: Registering gym trainers and assigning them to member schedules or slots.

Workout & Diet Planners: Custom daily exercise and meal charts for members.

Mobile Application: Building dedicated Android or iOS apps for easier mobile access.

Biometric/ID Attendance: Linking fingerprint scanners or QR codes at the gym door to the software.

CHAPTER 3 : SYSTEM REQUIREMENTS AND DESIGN

3.1 System Modules

The FitHub system is divided into four major modules, each handling a distinct part of the gym membership management process: the User Module, Membership Module, Payment Module, and Admin Module — plus supporting modules for the store, progress tracking, reviews, calendar and banners. Each module and its step-by-step working is explained below.

3.1.1 User Module

This module handles everything related to a user's identity and account on the platform.

Registration:

  • The new user opens the FitHub registration page and enters details such as name, email address, phone number and password (with confirm password).
  • The frontend validates the input fields (e.g., valid email format, 10-digit Indian mobile number, minimum 8-character password, matching passwords, required fields).
  • On submission, the data is sent to the backend registration API (POST /api/auth/register).
  • The server checks whether the email is already registered. If it exists, an error is returned.
  • If the email is new, the password is hashed with bcrypt and the user record is stored in MongoDB.
  • An email OTP is issued for account verification, and the user is redirected to the Login page with a success message.

Login:

  • The registered user enters their email and password on the login page.
  • The frontend checks that both fields are filled (empty fields trigger a "required" message).
  • Valid input is sent to the backend login API (POST /api/auth/login) as a JSON request.
  • The server verifies the credentials against the stored (hashed) password with bcrypt.
  • If valid, a signed JWT token is created and the user is redirected to the dashboard (members) or admin panel (role = admin); if invalid, an error message is displayed.

Forget Password:

  • The user clicks "Forgot Password" on the login page.
  • The user enters their registered email address.
  • The system generates a time-limited email OTP and sends it to the user's email.
  • The user enters the OTP and sets a new password.
  • The new password is validated and updated in the database (re-hashed with bcrypt).

Profile Management:

  • The logged-in user navigates to the "My Profile" section.
  • Existing details (name, phone, date of birth, gender, address, emergency contact) are fetched from the database and displayed.
  • The user edits the required fields and clicks "Save"/"Update".
  • The updated data is validated and saved back to the database.

3.1.2 Membership Module

This module allows users to browse, purchase, and track gym membership plans.

View Membership Plans:

  • The user opens the "Membership Plans" page.
  • The system fetches all active plans (name, duration + unit, price, features, popular flag) from the database (GET /api/subscriptions/all) and displays them as cards.

Compare Plans:

  • The user selects two or more plans to compare.
  • The system displays a side-by-side table of features, duration, and price for easy comparison.

Buy Membership:

  • The user selects a plan and clicks "Buy Membership".
  • The system checks whether the user is logged in; if not, the user is redirected to login first.
  • The user confirms the plan and chooses online payment (Razorpay Checkout) or pay-at-gym.
  • Once payment succeeds, a new membership record is created with start date, end date (auto-calculated from duration), and "active" status (POST /api/members/:id/membership).

Renew Membership:

  • An existing member opens "Renew Membership" from their dashboard, usually shown before/after expiry.
  • The user selects the same or a new plan and proceeds to payment.
  • On successful payment, the membership end date is extended and status is updated.

Membership History:

  • The user opens "Membership History" / "Transactions" to view all past and current memberships along with payment status, amounts paid/remaining and receipts.

3.1.3 Payment Module

This module manages the financial transactions of the platform.

Online Payment:

  • After selecting a plan, the user is directed to the payment page.
  • The user pays through Razorpay Checkout (card/UPI/net-banking) or chooses pay-at-gym.
  • The payment request is sent securely to the gateway/backend for processing and the Razorpay signature is verified on the server (POST /api/payment/verify).

Payment Confirmation:

  • The payment gateway/backend validates the transaction.
  • On success, the payment status is marked "paid" and linked to the corresponding membership.
  • On failure, the status is marked "failed" and the user is prompted to retry.
  • Partial / installment payments are supported: the admin records each installment and the server rejects any amount exceeding the remaining balance (HTTP 400 overpay guard).

Download Receipt:

  • Once payment is confirmed, the system generates a receipt containing transaction ID, amount, date, method and plan details.
  • The user can view, print or download this receipt from their dashboard/history, and a copy is emailed automatically on every purchase or recorded installment.

3.1.4 Admin Module

This module gives the gym administrator control over users, plans, and payments.

Manage Members:

  • The admin logs into the Admin Dashboard and opens the "Members" section.
  • The admin can view all members with search, add new members (optionally enrolling them in a plan in the same step), edit details, change/assign plans, or remove member accounts.

Manage Membership Plans:

  • The admin opens "Manage Plans" to add a new plan (name, duration, price, features, popular flag) or edit/deactivate an existing plan.

Approve Payment:

  • The admin reviews paid/partial/pending memberships in the "Payments" section (GET /api/members with payment totals).
  • The admin records cash/UPI/card installments per member (POST /api/members/:id/payment) and the ledger updates instantly.

Send Notification:

  • The system automatically emails a branded payment receipt on every purchase or installment.
  • A scheduled job (every 6 hours) emails members upcoming-expiry reminders and flags them so nobody is reminded twice.

View Reports:

  • The admin opens the dashboard to view total members, revenue collected, active/expiring/expired membership counts, and the full transaction ledger with per-record receipts.

3.1.5 Supporting Modules

  • Store & Orders — product catalog with stock tracking, cart, checkout (Razorpay/cash), order status and order receipts.
  • Progress Tracking — members log weight and body measurements over time with charts.
  • Reviews — members submit ratings/comments; admin approves or hides them.
  • Calendar & Banners — admin-published gym classes, events, holidays and homepage banners.
